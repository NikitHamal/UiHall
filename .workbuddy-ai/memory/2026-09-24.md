## Fix: index.html opened from disk came up empty

Nikit double-clicked `ui-hall/index.html` and got a blank page plus a CORS error
(`blocked by CORS policy` / `net::ERR_FAILED` on `data/corpus.json`).

**Cause.** A browser blocks `fetch()` on `file://` URLs — the origin is `null`, so every
request is treated as cross-origin. `data.js` line 3 had a comment claiming the site "runs
from file:// as well as a server". It did not. The comment was a lie I had written.

**Fix — two load paths, one source of truth.**

- `tools/build_corpus.py` now also emits `ui-hall/data/corpus.js`
  (`window.STORMY_CORPUS = {...}`), a generated twin. `corpus.json` remains the single
  source of truth because the MCP reads it from disk. U+2028/2029 escaped for safety.
- `assets/js/data.js` picks the path: on `file://` it injects a classic `<script>` tag for
  `corpus.js` (classic scripts are *not* blocked, unlike ES modules); on `http(s)` it
  fetches the JSON and only falls back to the script if the fetch fails. The script is
  injected on demand, so http never downloads the data twice.

**Verified.** New harness `tools/verify_file_url.mjs` — 10 assertions over `file://`,
including that a `.webm` clip actually decodes from disk (`readyState >= 2`,
`videoWidth > 0`). Note the scripts are classic, not modules, which is why only `fetch` was
the blocker.

| check | before | after |
|---|---|---|
| http (`verify_ui.mjs`) | 43/43 | 43/43 |
| file:// (`verify_file_url.mjs`) | 0 cards, blank | **10/10** |
| MCP (`selftest.js`) | 69/69 | 69/69 |

**Also fixed while in there.** `verify_ui.mjs` had the same fragility `shoot.mjs` had: it
depended on a server started by the calling shell, so a reaped background process made
every assertion fail on `ERR_CONNECTION_REFUSED` and looked like an app regression. It now
starts and stops its own server like `shoot.mjs`.

**Added.** `start.cmd` — one-click launcher for the http route (shareable URL, Range
requests for video seeking). Prefers the managed node binary, falls back to `node` on PATH.

**README** had an explicit "`file://` will not work" section with a hand-rolled inline
server one-liner. Replaced with the accurate two-path explanation.

## UI Hall redesigned — it is now the first thing built with the skill

Nikit's call: *"it is a shame that we are building mcp and skills for ui ux while our own ui
hall's ui ux is poor... it has no fonts, the dropdowns and other components are all browser
defaults."* He was right. A design catalogue using native widgets undermines the whole
premise.

### Type

Shipped **Inter Variable** (`ui-hall/assets/fonts/InterVariable.woff2`, 352 KB, SIL OFL 1.1)
from the official rsms/inter v4.1 release. One file covers weights 100–900 plus an
optical-size axis, replacing nine static faces. `font-optical-sizing: auto` on `body`;
tracking is now per-size (`--ls-tight` display / `--ls-snug` headings / `--ls-flat` body /
`--ls-wider` micro-labels) instead of one value for the page.

Fallback stack includes **Noto Sans and Nirmala UI** because the corpus contains 7
Devanagari glyphs, which Inter does not cover — without that, tofu.

### Controls — all custom now

- **`assets/js/listbox.js` (new)** — an ARIA listbox replacing the native `<select>` popup.
  Progressive enhancement: the real `<select>` stays in the DOM as the value/event source
  (clipped, `aria-hidden`), so every existing `el.value` read and `change` listener kept
  working untouched. Full keyboard support, type-ahead, `aria-activedescendant`, flip-up
  when there is no room below, Escape closes, focus returns to the trigger.
- **Range slider** — native input kept for a11y, track and thumb replaced via
  `::-webkit-slider-runnable-track` / `-thumb` and `::-moz-range-*`. The filled portion
  comes from a `--fill` CSS variable computed in JS, because a gradient cannot know where
  the thumb is.
- Focus ring, tabular numerals, themed scrollbar, `::selection`, press states, loading
  skeleton — all added.

### The bug that cost a cycle

`if (window.Listbox)` was always false. A top-level `const` in a **classic script** lives in
the global *lexical* scope: reachable as a bare identifier, but **not** a property of
`window`. The other modules (`DATA`, `Filters`) are referenced as bare identifiers for
exactly this reason. Fix: `typeof Listbox !== 'undefined'`. Worth remembering — `typeof X`
works for script-scoped consts, `window.X` does not.
